# REFIT washing-machine disaggregation

A small, reproducible pipeline on the **REFIT Electrical Load Measurements** dataset (20 UK homes):

1. **Clean raw data** for House 1 at 1-minute resolution ([DATA.md](DATA.md)).
2. **Explore washing-machine use** in six homes from the official clean data ([RESULTS.md](RESULTS.md) §2).
3. **Estimate washing-machine power from the whole-home signal** with LightGBM, compared against
   simple baselines on a house the model has never seen ([RESULTS.md](RESULTS.md) §3).
4. **Practical implications** for a utility ([Recommendation.md](Recommendation.md)).

## Repository layout

```
src/config.py          data paths, appliance channels, plot colours
src/clean_house1.py    Section 1: inspect + clean raw House 1 (Part1 + Part2) -> 1-minute
src/check_parts.py     diagnostic used to find the Part1/Part2 overlap (kept for transparency)
src/clean_data.py      loads CLEAN_House{n}.csv -> 1-minute cache (outputs/clean_1min/)
src/wm_eda.py          Section 2: cycle detection, statistics and EDA plots
src/model.py           Section 3: baselines, LightGBM models, metrics and plots
docs/                  REFIT clean-data readme (appliance lists)
figures/               all plots referenced in the markdown files
outputs/               generated tables (quality report, outages, cycles, metrics)
```

## Setup and run (Windows cmd; macOS/Linux equivalents in brackets)

Requires Python 3.11+ (developed on 3.11.9; package versions pinned in `requirements.txt`).

```
git clone https://github.com/khyatinagaria/flock_AI_KHYATI_NAGARIA.git
cd flock_AI_KHYATI_NAGARIA
python -m venv .venv
.venv\Scripts\activate.bat            [source .venv/bin/activate]
pip install -r requirements.txt
```

Download and extract the two archives from the
[REFIT dataset page](https://pureportal.strath.ac.uk/en/datasets/refit-electrical-load-measurements/)
(`REFIT_RAW_081116.7z`, `CLEAN_REFIT_081116.7z`) into your **Downloads** folder, so that these exist:

```
~/Downloads/REFIT_RAW_081116/RAW_House1_Part1.csv, RAW_House1_Part2.csv
~/Downloads/CLEAN_REFIT_081116/CLEAN_House2.csv ... CLEAN_House17.csv
```

Elsewhere? Set `REFIT_RAW_DIR` and `REFIT_CLEAN_DIR` environment variables to the two folders.

Then run, in order, from the repository root (or just `run_all.bat`):

```
python src\clean_house1.py     ~1 min   Section 1
python src\wm_eda.py           ~5 min first time (builds the 1-minute cache), then seconds
python src\model.py            ~10-20 min on a laptop (three LightGBM models)
python src\loho.py             ~10-60 min (leave-one-house-out, 6 folds)
```

Every table and figure in the markdown files is regenerated by these commands. Random seeds are
fixed (`SEED = 0`). **Reproducibility check:** the repository was cloned into a fresh folder with a new
virtual environment and `run_all.bat` was run end to end (about 15 minutes on a laptop). The cleaning,
EDA and main model outputs matched the committed results exactly; in the leave-one-house-out run, one
fold (House 9) differed in the third significant digit (e.g. energy error +244.9% vs +244.2%), which is
expected from multithreaded LightGBM training.

## Key decisions and assumptions

- **Raw timestamps are UK clock time.** The raw logger's `Unix` column equals the local `Time`
  string, with a repeated hour every autumn and a missing hour every spring; we convert to UTC.
- **Raw Part1 and Part2 overlap by ~3 months**; Part1 is kept for the overlap. Part2 writes sparse
  rows (blank = not reported), so rows sharing a timestamp are merged per channel.
- **Physical limits, not statistical outlier rules**: appliance > 4 kW (13 A plug limit) and
  aggregate > 20 kW are set to missing; everything else is kept, including ~10 kW showers.
- **Gaps**: up to 5 minutes interpolated, longer gaps flagged and excluded, never filled.
- **Washing-machine "running"**: 1-minute power above 20 W; cycles join pauses of up to 10 minutes
  and must last 10 minutes, peak at 200 W and use 0.05 kWh.
- **1-minute means** of ~8 s readings: enough to see a cycle's heating, wash and spin phases while
  keeping the data volume manageable on a laptop.

## Validation design

Split **by house**, never by random minutes: train on Houses 2, 5, 7 and 9; House 15 is used only
for early stopping and for choosing the detection threshold; **House 17 is the test house**. All
features are computed inside one house's own time series, so nothing from the test home (not even
neighbouring minutes, which a random split would leak through overlapping windows) reaches training.
This matches the realistic use case: estimating appliance use for a customer we have no sub-metering
for. Because one test house is a small sample, the frozen design is also evaluated with
**leave-one-house-out** (`src/loho.py`): six folds, each house held out once, with the next house as
validation and the other four for training (RESULTS.md §3.8).

## Trade-offs

- **LightGBM on hand-made window features instead of a neural network (e.g. Seq2Point)**: trains in
  minutes on a CPU, is easy to inspect (feature importance), and the assessment values clarity
  over complexity. A CNN would likely learn the cycle shape better but needs a GPU and more tuning.
- **Two-stage "detect then estimate"** instead of a single regressor: a single regressor minimises
  average error by smearing small predictions over the 95% of minutes when the machine is off;
  separating detection from power estimation gives cleaner on/off output and better watts while
  running, at the cost of one threshold to tune.
- **Centred windows (±60 min)** use future data: fine for monthly bills or after-the-fact insight,
  not for real-time alerts without a delay.
- **Six houses** instead of all twenty: chosen for a clean single-machine channel; enough to show
  cross-house variation within the time budget.

## Possible improvements

1. **More homes**: extend leave-one-house-out (done for six homes) to the other REFIT
   washing-machine homes, especially ones with washer-dryers, which caused the largest errors.
2. **Seq2Point CNN** (Zhang et al., 2018) on the same split, compared against this LightGBM.
3. **Use REFIT's `Issues` flag** to drop minutes where sub-meters exceed the aggregate.
4. **Cycle-level evaluation** (detected vs true cycles, energy per cycle), which is what a customer
   insight would use.
5. **Calibrate per house** with a few labelled cycles (for example from a customer survey), since
   the model's main error is house-specific false alarms.

## References

- Murray, D., Stankovic, L. and Stankovic, V. (2017). An electrical load measurements dataset of
  United Kingdom households from a two-year longitudinal study. *Scientific Data* 4, 160122.
  (REFIT dataset description; cited per the readme.)
- Kelly, J. and Knottenbelt, W. (2015). Neural NILM: Deep neural networks applied to energy
  disaggregation. *BuildSys '15*. (Uses UK-DALE rather than REFIT, but its washing-machine settings
  and evaluation protocol are widely reused in later REFIT studies.) Adopted: 20 W on-threshold for washing machines; evaluating on a
  house not seen in training; on/off precision, recall and F1 next to power errors.
- Zhang, C., Zhong, M., Wang, Z., Goddard, N. and Sutton, C. (2018). Sequence-to-point learning with
  neural networks for non-intrusive load monitoring. *AAAI*. Adopted: predict the appliance power at
  one minute from a window of aggregate readings around it (our ±60-minute feature window), and
  testing on REFIT houses held out from training.
